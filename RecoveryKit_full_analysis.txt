RECOVERY KIT — ПОЛНЫЙ АНАЛИЗ ИСХОДНОГО КОДА

1. ОБЩАЯ СТРУКТУРА

Recovery Kit представляет собой набор инструментов для восстановления и диагностики Windows. В проекте отдельно реализованы:

- восстановление системных политик;
- работа с реестром;
- работа с процессами;
- работа со службами;
- работа с Task Scheduler;
- работа с файлами;
- восстановление загрузки Windows;
- работа с EFI;
- работа с WinRE;
- работа с offline Registry hives;
- операции с защищёнными системными файлами;
- отдельные функции для IFEO, AppInit_DLLs, sethc.exe и utilman.exe.

ВАЖНО:
Наличие функции в исходном коде не означает, что она автоматически выполняется при запуске Full Recovery. Большинство дополнительных функций вызываются отдельно.

2. FULL RECOVERY

Основная последовательность Full Recovery реализована через TRecoveryController.RunFullRecovery.

Последовательность операций:

1. CMD
   Удаляется DisableCMD.

2. Run
   Удаляется NoRun.

3. Ctrl+Alt+Del
   Удаляются ограничения DisableCAD.

4. Power Button
   Восстанавливаются политики, блокирующие выключение и перезагрузку.

5. Control Panel
   Удаляется NoControlPanel.

6. Cursor Suppression
   Восстанавливаются параметры подавления курсора.

7. Device Manager
   Удаляются NoDeviceManagerPage и NoDevMgrPage.

8. DisallowRun / RestrictRun
   Удаляются соответствующие политики и их значения.

9. NumLock
   InitialKeyboardIndicators устанавливается в значение 2.

10. Hotkeys
    Удаляются ограничения горячих клавиш, включая связанные параметры Alt+Tab, Windows-клавиш, Task Manager, Win+L и Scancode Map.

11. RU/EN и Alt+Shift
    Восстанавливаются параметры раскладки и переключения языков.

12. Account Settings
    Восстанавливаются ограничения переключения пользователя, выхода, смены пароля, блокировки рабочей станции и связанные политики.

13. Hidden Files
    Восстанавливается отображение скрытых и системных файлов.

14. Logoff
    Убираются ограничения выхода из системы.

15. Switch User
    Убираются ограничения переключения пользователя.

После выполнения этих операций отдельно выполняется очистка IFEO Debugger.

3. ЧТО ПРОИСХОДИТ ПРИ FULL RECOVERY

Упрощённая схема:

RecoveryKit.exe
    |
    v
TRecoveryController.RunFullRecovery
    |
    +-- Repair CMD
    +-- Repair Run
    +-- Repair CAD
    +-- Repair Power
    +-- Repair Control Panel
    +-- Repair Cursor
    +-- Repair Device Manager
    +-- Repair DisallowRun / RestrictRun
    +-- Repair NumLock
    +-- Repair Hotkeys
    +-- Repair RU/EN
    +-- Repair Account Settings
    +-- Repair Hidden Files
    +-- Repair Logoff
    +-- Repair Switch User
    |
    v
IFEO cleanup
    |
    v
завершение операции

Основная работа Full Recovery происходит через Registry.

4. РЕЕСТР

Используются, среди прочего, следующие ветки:

HKCU\Software\Policies\Microsoft\Windows\System

HKCU\Software\Microsoft\Windows\CurrentVersion\Policies\Explorer

HKCU\Software\Microsoft\Windows\CurrentVersion\Policies\System

HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System

HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon

HKCU\Control Panel\Keyboard

HKU\.DEFAULT\Control Panel\Keyboard

HKLM\SYSTEM\CurrentControlSet\Control\Keyboard Layout

HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced

Основной принцип:
Recovery Kit преимущественно удаляет значения политик, которые блокируют штатные функции Windows, а не создаёт собственную систему политик.

Отдельные параметры восстанавливаются явной записью. Пример:

InitialKeyboardIndicators = 2

5. FILESYSTEM ПРИ FULL RECOVERY

Обычный Full Recovery не требует постоянной рабочей папки и в основном работает через Registry.

В DEBUG-сборке предусмотрен лог:

<каталог программы>\Logs\RecoveryKit.log

Однако запись этого лога зависит от DEBUG-сборки.

Поэтому нельзя считать, что обычная release-сборка всегда создаёт Logs\RecoveryKit.log.

6. TASK SCHEDULER

Есть отдельная функция установки запуска RecoveryKit через Task Scheduler.

Она может:

1. определить подходящий существующий каталог;
2. выбрать вложенный каталог;
3. сгенерировать имя EXE;
4. скопировать туда RecoveryKit;
5. зарегистрировать Scheduled Task.

В исходнике рассматриваются каталоги, связанные с:

%ProgramData%
%PUBLIC%
%TEMP%
<системный диск>\ProgramData

Имя EXE генерируется на основе GUID.

Задача называется:

RecoveryKit

Автор:

RecoveryKit

Описание указывает на запуск RecoveryKit при входе в Windows.

Для запуска используется аргумент:

-RePaint

ВАЖНО:
Это отдельная функция. Она не является частью стандартного Full Recovery.

7. SYSTEM\SETUP\CMDLINE

Есть отдельный механизм работы с:

HKLM\SYSTEM\Setup

и значениями:

CmdLine
SetupType

В соответствующей функции RecoveryKit может использовать:

C:\Windows\System32\RKit.exe

После настройки CmdLine может указывать на этот исполняемый файл, а SetupType устанавливается в 2 при соответствующем условии.

Это отдельная функция и не выполняется автоматически Full Recovery.

8. WINRE

Recovery Kit умеет модифицировать Windows Recovery Environment.

Основной объект:

winre.wim

Типичный алгоритм:

1. определяется расположение WinRE;
2. находится winre.wim;
3. создаётся временная папка;
4. WIM монтируется через DISM;
5. содержимое доступно как файловая система;
6. выполняются необходимые изменения;
7. WIM размонтируется с Commit;
8. временные данные удаляются.

Временный каталог:

%TEMP%\WinRE_Mount_<GUID>

Если оригинальный WIM нельзя корректно использовать напрямую, создаётся рабочая копия:

%TEMP%\winre_work_<GUID>.wim

После изменения рабочая копия может использоваться для замены исходного WIM.

В отдельных сценариях код использует:

reagentc /disable
reagentc /enable

для отключения и повторного включения WinRE.

9. BOOT RECOVERY

Boot Recovery работает с загрузочными компонентами Windows.

Общий процесс:

1. сканирование дисков;
2. поиск установленной Windows;
3. определение системного и EFI-раздела;
4. назначение временных букв при необходимости;
5. запуск BCDBoot;
6. проверка результата;
7. удаление временных назначений.

Используется:

\Windows\System32\bcdboot.exe

10. EFI

Есть отдельная функция восстановления/создания EFI System Partition.

Общий процесс:

1. сканирование физического диска;
2. анализ существующих разделов;
3. поиск свободного места;
4. проверка требований к размеру и выравниванию;
5. создание временного DiskPart script;
6. запуск diskpart.exe;
7. создание EFI System Partition;
8. повторная проверка диска;
9. проверка созданного ESP.

Временный файл:

%TEMP%\RecoveryKit_ESP_<GUID>.txt

После завершения операции он удаляется.

В исходнике предусмотрены минимальные размеры:

512-byte sectors: 100 MB
4Kn sectors: 260 MB
default size: 260 MB

11. OFFLINE REGISTRY

Recovery Kit умеет работать с Registry hive, который не принадлежит текущей загруженной Windows.

Используется схема:

RegLoadKey
    |
    v
offline hive
    |
    v
изменение
    |
    v
сохранение
    |
    v
RegUnLoadKey

При необходимости создаётся временная копия hive.

Предусмотрена backup-схема с расширением:

.bak

Общий принцип:

original hive
    |
    +-- temporary hive
    |
    +-- backup
    |
    +-- replacement
    |
    +-- reload

Это позволяет откатить операцию при ошибке.

12. TASK XML BACKUP / ROLLBACK

При изменении XML задания предусмотрена защитная схема.

Могут появляться:

<task>.RecoveryKit.<GUID>.tmp
<task>.RecoveryKit.<GUID>.bak

Алгоритм:

1. читается исходный XML;
2. формируется изменённая версия;
3. новая версия записывается в .tmp;
4. выполняется FlushFileBuffers;
5. исходный вариант сохраняется как backup;
6. новый XML становится рабочим;
7. выполняется проверка;
8. после успеха backup удаляется.

При ошибке новый файл удаляется, а backup возвращается.

13. УДАЛЕНИЕ TASK

При отдельной операции удаления задания используется промежуточное имя:

<task>.RecoveryKit.Delete.<GUID>

Также сохраняется информация TaskCache.

Для backup используются элементы вида:

RecoveryKitBackup\TaskCache_<GUID>

При успешной операции временные данные очищаются.

При ошибке предусмотрено восстановление исходного состояния.

14. ЗАЩИЩЁННЫЕ ФАЙЛЫ

В проекте есть отдельные модули для работы с защищёнными объектами Windows.

Связанные компоненты:

uFileUnprotectUtils
uOpenPathUnprotectUtils
uDirectoryUnprotectUtils
uFileSecurityUtils
uTrustedInstallerLaunch

Используются механизмы:

- ownership;
- DACL;
- Administrators;
- Windows privileges;
- TrustedInstaller.

Это позволяет отдельным функциям работать с объектами, к которым обычный процесс не имеет достаточного доступа.

15. IFEO

Recovery Kit отдельно работает с:

HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options

и связанными Debugger-параметрами.

В Full Recovery выполняется отдельная очистка IFEO Debugger.

Алгоритм:

1. перечисляются соответствующие IFEO-разделы;
2. проверяется наличие Debugger;
3. найденные Debugger значения удаляются.

ВАЖНО:
Это не то же самое, что удаление всех IFEO-разделов. Целевой объект — соответствующие Debugger entries.

16. APPINIT_DLLS

В проекте есть отдельная функциональность работы с:

HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Windows\AppInit_DLLs

и соответствующими параметрами.

Эта функция не является обязательной частью Full Recovery.

17. SETHC.EXE И UTILMAN.EXE

В исходниках присутствуют отдельные операции с:

C:\Windows\System32\sethc.exe

C:\Windows\System32\utilman.exe

Они относятся к отдельному функционалу восстановления/замены системных компонентов.

Их наличие в исходниках не означает автоматическую замену при Full Recovery.

18. ПРОЦЕССЫ

Recovery Kit имеет отдельный процессный модуль.

Он может:

- перечислять процессы;
- строить дерево процессов;
- получать путь EXE;
- проверять цифровую подпись;
- рассчитывать MD5;
- завершать процессы;
- работать с отдельными системными/critical process сценариями.

Это отдельная диагностическая/административная часть программы.

19. СЛУЖБЫ

Есть работа через Windows Service Control Manager.

Функциональность включает:

- перечисление служб;
- получение состояния;
- запуск;
- остановку;
- перезапуск;
- операции изменения состояния.

20. ФАЙЛЫ

Файловый модуль умеет:

- искать файлы;
- удалять;
- перемещать;
- переименовывать;
- получать свойства;
- считать MD5;
- проверять цифровые подписи;
- анализировать путь и имя;
- искать потенциально подозрительные признаки.

21. ЧТО МОЖЕТ СОЗДАВАТЬСЯ В TEMP

Основные обнаруженные шаблоны:

%TEMP%\WinRE_Mount_<GUID>
%TEMP%\winre_work_<GUID>.wim
%TEMP%\RecoveryKit_ESP_<GUID>.txt

Также временные файлы могут появляться при работе с Task XML и offline Registry.

Большинство из них предназначено для временной работы и удаляется после успешного завершения.

22. СВОДНАЯ ТАБЛИЦА

Объект | Когда используется | Возможный путь | Постоянность

RecoveryKit.log | DEBUG logging | <RecoveryKit>\Logs\RecoveryKit.log | зависит от сборки

WinRE mount | изменение WinRE | %TEMP%\WinRE_Mount_<GUID> | временный

RKit.exe | Setup CmdLine функция | C:\Windows\System32\RKit.exe | может остаться

23. ЧТО НЕ ДЕЛАЕТ FULL RECOVERY

Full Recovery не означает автоматическое выполнение всех функций проекта.

При стандартном RunFullRecovery автоматически не следует считать выполняемыми:

- создание EFI;
- BCDBoot repair;
- изменение winre.wim;
- создание Scheduled Task;
- копирование RecoveryKit в случайный каталог;
- установку RKit.exe;
- работу с AppInit_DLLs;
- операции sethc.exe;
- операции utilman.exe;
- запуск TrustedInstaller;
- полное редактирование offline Registry;
- операции со службами;
- операции с файлами.

Это отдельные функции программы.

24. ИТОГОВАЯ МОДЕЛЬ

RecoveryKit можно условно разделить на четыре уровня.

Уровень 1 — обычный Recovery:

Registry policies
Explorer restrictions
Keyboard
Hotkeys
Accounts
Hidden files
IFEO

Уровень 2 — системное восстановление:

SFC
DISM
Services
Processes
Task Scheduler
Protected files

Уровень 3 — offline recovery:

Offline Registry
WinRE
WIM
EFI
BCD
BCDBoot
DiskPart

Уровень 4 — специальные механизмы:

AppInit_DLLs
IFEO Debugger
sethc.exe
utilman.exe
Setup CmdLine
Scheduler-based launch

Главный вывод:

RecoveryKit не является одним линейным скриптом, который при запуске автоматически выполняет все перечисленные действия. Это большая оболочка над набором независимых recovery-инструментов. Full Recovery в первую очередь снимает Windows-политики и ограничения через Registry и отдельно очищает IFEO Debugger. Остальные глубокие операции с WinRE, EFI, BCD, offline Registry, Scheduler и системными файлами вызываются отдельными функциями.
