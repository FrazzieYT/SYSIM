RecoveryKit — функция «Восст. системн. файлы» в среде WinRE
================================================================

ОБЪЕКТ АНАЛИЗА
----------------
На скриншоте показан блок:

    В среде WinRE
    Восст. системн. файлов
    Диск назначения: C:
    [Восст. системн. файлы]

Это не обычный SFC /scannow и не DISM RestoreHealth.

По исходному коду кнопка вызывает отдельную функцию:
    TfMain.btnRecoveryFileSystemClick

Файл:
    uMain.pas

Связанный модуль:
    Source\ApplicationUtils\uSevenZipResourceExtractor.pas

Ресурсы:
    RecoveryKitResource.rc
    Source\RecoveryWindows\7z.dll
    Source\RecoveryWindows\Win10\Win10


1. ЧТО ПРОИСХОДИТ ПРИ НАЖАТИИ КНОПКИ
-------------------------------------

Обработчик кнопки делает по сути четыре действия:

1) получает системный TEMP-каталог;
2) извлекает встроенный в RecoveryKit ресурс 7z.dll во временный каталог;
3) берёт встроенный ресурс Win10;
4) асинхронно распаковывает этот 7z-архив прямо в выбранный диск Windows.

Упрощённая цепочка:

    Кнопка
       |
       v
    btnRecoveryFileSystemClick
       |
       +--> TryGetTempDirectory
       |
       +--> извлечение ресурса "7z" -> %TEMP%\7z.dll
       |
       +--> выбранный диск, например C:\
       |
       +--> ресурс "Win10"
       |
       +--> 7z.dll
       |
       v
    распаковка файлов
       |
       v
    C:\Windows\...
    C:\...


2. ТОЧНЫЙ КОД ОБРАБОТЧИКА
--------------------------

Исходник:

    procedure TfMain.btnRecoveryFileSystemClick(Sender: TObject);
    Const
      OK = ' .. Готов.';
      ERROR = ' .. Ошибка!';
    Var
      DestDir: String;
    begin
      btnRecoveryFileSystem.Enabled := False;
      TryGetTempDirectory(DestDir);
      EnsureRCDATAResourceInTemp('7z', '7z.dll', DestDir, False, False, '');

      var
      Drive := DriveComboBox1.Drive + ':\';
      StartExtract7zArchiveFromRCDATAAsync('Win10Files', Drive,
        procedure(const Success: Boolean; const ErrorText: String)
        begin
        end, DestDir + '7z.dll');
      btnRecoveryFileSystem.Enabled := True;
    end;

Ключевые моменты:

    Drive := DriveComboBox1.Drive + ':\';

Если в интерфейсе выбран C:, получается:

    C:\

Именно этот путь передаётся как корень назначения для распаковки.


3. ОТКУДА БЕРЁТСЯ 7z.dll
-------------------------

В RecoveryKit ресурс объявлен в:

    RecoveryKitResource.rc

Строка:

    7z RCDATA "Source\RecoveryWindows\7z.dll"

То есть DLL встроена внутрь EXE как ресурс RT_RCDATA.

При нажатии кнопки программа не ищет установленный 7-Zip.

Она извлекает собственную встроенную DLL.

Вызов:

    EnsureRCDATAResourceInTemp(
        '7z',
        '7z.dll',
        DestDir,
        False,
        False,
        ''
    );

`DestDir` предварительно получается через:

    TryGetTempDirectory(DestDir);

Поэтому типичный результат:

    %TEMP%\7z.dll

Параметр AOverwrite = False.

Это означает: если файл назначения уже существует, функция извлечения ресурса не обязана перезаписывать его.


4. ОТКУДА БЕРУТСЯ ВОССТАНАВЛИВАЕМЫЕ ФАЙЛЫ
-------------------------------------------

В ресурсах проекта есть:

    Win10 RCDATA "Source\RecoveryWindows\Win10\Win10"

Файл:

    Source\RecoveryWindows\Win10\Win10

имеет формат 7z-архива.

Он встроен в EXE как RT_RCDATA-ресурс с именем:

    Win10

В обработчике используется:

    StartExtract7zArchiveFromRCDATAAsync(
        'Win10Files',
        Drive,
        ...,
        DestDir + '7z.dll'
    );

Здесь есть важное различие имён:

    Win10       — имя ресурса в .rc
    Win10Files  — имя, передаваемое обработчику кнопки

В исходниках также присутствует генератор этого архива:

    Source\RecoveryWindows\Win10\Win10.ps1

В нём перечислены исходные файлы, которые должны попадать в архив Win10.


5. ЧТО ПРЕДУСМОТРЕНО В WIN10 АРХИВЕ
------------------------------------

В Win10.ps1 указаны такие элементы:

    C:\Windows\Fonts\Seg*.ttf
    C:\Windows\Fonts\tahom*.ttf
    C:\Windows\Fonts\micross.ttf
    C:\Windows\Fonts\arial.ttf

    C:\Windows\System32\cmd.exe
    C:\Windows\System32\LogonUI.exe
    C:\Windows\System32\taskmgr.exe
    C:\Windows\System32\sethc.exe
    C:\Windows\System32\Utilman.exe
    C:\Windows\System32\gpedit.msc
    C:\Windows\System32\msconfig.exe
    C:\Windows\explorer.exe
    C:\Windows\regedit.exe

Для масок `Seg*.ttf` и `tahom*.ttf` скрипт разрешает раскрытие масок.

ВАЖНО:
этот список относится к сценарию формирования Win10-архива. Фактический встроенный архив является уже подготовленным бинарным ресурсом `Win10`.


6. КУДА ИМЕННО РАСПАКОВЫВАЕТСЯ
--------------------------------

Если пользователь выбрал:

    C:

то:

    DriveComboBox1.Drive = C

и формируется:

    C:\

Если внутри архива есть:

    Windows\System32\cmd.exe

то конечный путь будет:

    C:\Windows\System32\cmd.exe

Если внутри архива есть:

    Windows\System32\sethc.exe

то:

    C:\Windows\System32\sethc.exe

Если внутри архива есть:

    Windows\Fonts\arial.ttf

то:

    C:\Windows\Fonts\arial.ttf

То есть буква диска не сохраняется как часть пути архива — архив содержит относительные пути, а они соединяются с выбранным корнем.


7. ПРОВЕРКА ПУТИ ПРИ РАСПАКОВКЕ
--------------------------------

Распаковщик не просто склеивает строки.

Перед созданием конечного пути вызывается:

    SanitizeAndCombineDestPath

Он:

1) заменяет `/` на `\`;
2) удаляет начальные `\`;
3) запрещает путь с собственной буквой диска, например:
       C:\...
4) строит абсолютный путь относительно выбранного корня;
5) проверяет, что получившийся путь остаётся внутри выбранного каталога.

Поэтому архивный путь вида:

    Windows\System32\cmd.exe

превращается в:

    C:\Windows\System32\cmd.exe

а попытка выйти из корня через `..\` должна быть отброшена.


8. КАК СОЗДАЁТСЯ ФАЙЛ
----------------------

Для файла используется:

    TFileStream.Create(
        LOutPath,
        fmCreate or fmShareDenyWrite
    );

То есть распаковщик создаёт/перезаписывает файл назначения.

Родительская папка предварительно создаётся через:

    ForceDirectories

Если папки нет, она создаётся.

Пример:

    C:\Windows\Fonts\

или

    C:\Windows\System32\

будет создана при необходимости.


9. ЭТО НЕ SFC
-------------

Несмотря на название «восстановление системных файлов», эта конкретная кнопка НЕ вызывает:

    sfc.exe /scannow

SFC находится в другом обработчике:

    TfMain.btnSFCClick

И кнопка SFC в интерфейсе называется:

    SFC /scannow

У неё отдельная логика.

В WinRE SFC запускается примерно так:

    sfc.exe /scannow
        /offbootdir=<boot-диск>
        /offwindir=<диск Windows>\Windows

А кнопка «Восст. системн. файлы» делает другое:

    распаковка заранее подготовленных файлов
    из встроенного архива
    прямо на выбранный Windows-диск.


10. КАК РАБОТАЕТ РАСПАКОВКА
----------------------------

Функция:

    StartExtract7zArchiveFromRCDATAAsync

создаёт отдельный поток:

    TSevenZipExtractThread

Он вызывает:

    Extract7zArchiveFromRCDATA

Дальше:

    TResourceStream.Create(
        HInstance,
        'Win10Files',
        RT_RCDATA
    )

получает встроенный архив.

Затем архив передаётся в:

    ExtractArchiveFromStream

с форматом:

    7z

и DLL:

    %TEMP%\7z.dll


11. ПОЧЕМУ ИСПОЛЬЗУЕТСЯ 7z.dll
-------------------------------

RecoveryKit не запускает:

    7z.exe

Вместо этого программа загружает библиотеку 7z.dll и работает с интерфейсами 7-Zip API.

В исходнике определены интерфейсы:

    IInArchive
    IArchiveExtractCallback
    ISequentialInStream
    ISequentialOutStream
    IProgress

Формат определяется как:

    CLSID_CFormat7z

Это позволяет программе распаковать встроенный архив без установки отдельного 7-Zip.


12. РАБОТА В ОТДЕЛЬНОМ ПОТОКЕ
------------------------------

Вызов:

    StartExtract7zArchiveFromRCDATAAsync(...)

не выполняет всю распаковку в UI-потоке.

Создаётся:

    TSevenZipExtractThread

и запускается:

    Result.Start;

Поэтому интерфейс программы не должен зависать на всё время распаковки.


13. ВАЖНАЯ ОСОБЕННОСТЬ ОБРАБОТЧИКА
------------------------------------

После запуска асинхронной распаковки код сразу выполняет:

    btnRecoveryFileSystem.Enabled := True;

То есть кнопка снова становится активной НЕ после завершения восстановления, а практически сразу после запуска фонового потока.

Callback завершения выглядит так:

    procedure(const Success: Boolean; const ErrorText: String)
    begin
    end

Он пустой.

Следовательно, именно этот обработчик:

- не показывает сообщение «Готово»;
- не показывает текст ошибки;
- не ждёт завершения распаковки;
- не содержит отдельной логики отката;
- не удаляет восстановленные файлы после ошибки.

Ошибки/пропуски обрабатываются внутри общего 7z-распаковщика.


14. ЧТО ПРОИСХОДИТ, ЕСЛИ ФАЙЛ ЗАНЯТ
------------------------------------

При создании файла:

    TFileStream.Create(... fmCreate ...)

может возникнуть ошибка доступа, например если файл занят или защищён.

В таком случае элемент помечается как пропущенный.

В распаковщике есть:

    FSkippedCount

и сообщения вида:

    Пропуск ...

После завершения распаковщик может сообщить количество пропущенных файлов.

Важно:
это не полноценный rollback.

Если часть файлов уже была заменена, а следующий файл не удалось записать, автоматически восстановить предыдущие файлы назад эта функция не пытается.


15. ВАЖНО: НЕТ BACKUP СИСТЕМНЫХ ФАЙЛОВ В ЭТОМ ОБРАБОТЧИКЕ
---------------------------------------------------------

В `btnRecoveryFileSystemClick` перед распаковкой не видно отдельной операции вида:

    Windows\System32\file.exe
        ->
    Windows\System32\file.exe.bak

или:

    copy original -> backup

Кнопка просто запускает извлечение архива в выбранный корень.

Поэтому наличие резервной копии зависит от других механизмов Windows/файловой системы, а не от этого конкретного обработчика.


16. ЧТО СОЗДАЁТСЯ В TEMP
------------------------

Минимально необходимый вспомогательный файл:

    %TEMP%\7z.dll

Это извлечённая из EXE встроенная библиотека.

Сам архив Win10 не обязательно сохраняется в виде отдельного файла на диске.

Он читается непосредственно из:

    RT_RCDATA

ресурса EXE.

То есть схема такая:

    RecoveryKit.exe
         |
         +-- встроенный 7z.dll
         |
         +-- встроенный Win10 7z-архив
                 |
                 v
             распаковка
                 |
                 v
             C:\Windows\...


17. ЧТО ПРОИСХОДИТ С АРХИВОМ
-----------------------------

Отдельный файл:

    %TEMP%\Win10.7z

для самой кнопки не создаётся.

`TResourceStream` читает ресурс прямо из EXE.

Поэтому:

    RecoveryKit.exe
        -> RT_RCDATA "Win10Files"
        -> поток
        -> 7z.dll
        -> файлы назначения

А не:

    RecoveryKit.exe
        -> Win10.7z
        -> запуск 7z.exe
        -> C:\...


18. ПРИМЕР ДЛЯ C:
-----------------

Допустим, пользователь загрузился в WinRE.

Выбрал:

    C:

и нажал:

    Восст. системн. файлы

Получается:

    Drive = "C:\"

Дальше программа получает:

    %TEMP%\7z.dll

и распаковывает встроенный Win10-архив.

Например:

    Windows\System32\cmd.exe
        ->
    C:\Windows\System32\cmd.exe

    Windows\System32\sethc.exe
        ->
    C:\Windows\System32\sethc.exe

    Windows\System32\Utilman.exe
        ->
    C:\Windows\System32\Utilman.exe

    Windows\explorer.exe
        ->
    C:\Windows\explorer.exe

    Windows\Fonts\*.ttf
        ->
    C:\Windows\Fonts\*.ttf


19. ЧЕМ ЭТА ФУНКЦИЯ ОТЛИЧАЕТСЯ ОТ SFC
--------------------------------------

«Восст. системн. файлы»:

    источник:
        встроенный архив RecoveryKit

    действие:
        распаковка файлов

    назначение:
        выбранный offline-диск Windows

    инструмент:
        встроенный 7z.dll

    механизм:
        прямое создание/перезапись файлов

    SFC:
        НЕ запускается


SFC /scannow:

    источник:
        хранилище компонентов Windows / WinSxS

    действие:
        проверка целостности и попытка восстановления

    инструмент:
        sfc.exe

    режим WinRE:
        /offbootdir
        /offwindir


20. ЧТО ПРОИСХОДИТ С ПРАВАМИ
-----------------------------

Этот конкретный обработчик сам по себе не содержит вызова:

    TrustedInstaller

и не содержит здесь отдельного изменения owner/DACL перед распаковкой.

Он передаёт путь непосредственно файловому распаковщику.

Если Windows не позволяет создать/перезаписать конкретный файл, файл может быть пропущен.

В проекте существуют отдельные модули работы с защищёнными файлами и TrustedInstaller, но они не вызываются непосредственно из показанного обработчика кнопки.

23. ВАЖНЫЕ ВЫВОДЫ
------------------

1. Кнопка не делает полноценную диагностику Windows.

2. Она не запускает SFC.

3. Она не запускает DISM.

4. Она не строит новый WinRE.

5. Она не монтирует WIM.

6. Она берёт заранее встроенный архив.

7. Архив распаковывается на выбранный диск Windows.

8. Пути внутри архива являются относительными.

9. Файл `C:\Windows\System32\...` может быть создан/перезаписан напрямую.

10. Перед распаковкой извлекается `7z.dll` во временный каталог.

11. Сам архив `Win10` читается из ресурсов EXE, а не обязательно записывается отдельным `.7z` файлом.

12. Отката уже заменённых файлов в этом обработчике нет.

13. Если отдельный файл нельзя записать, распаковщик может его пропустить.

14. Функция запускается асинхронно.

15. Callback завершения в обработчике кнопки пустой.

16. Поэтому визуально кнопка может снова стать активной раньше фактического окончания восстановления.

25. КОРОТКО
----------

Эта функция работает не как:

    «проверить Windows и автоматически починить всё».

Она работает как:

    «взять заранее подготовленный набор файлов,
     выбрать диск Windows,
     распаковать набор на этот диск,
     сохранив относительную структуру каталогов».

Для C: это фактически:

    встроенный Win10-архив
            ↓
        7z.dll
            ↓
          C:\
            ↓
    C:\Windows\System32\...
    C:\Windows\Fonts\...
    C:\Windows\...


Ключевое отличие от SFC:

    SFC = проверяет/восстанавливает через механизм Windows.

    Эта кнопка = напрямую раскладывает заранее подготовленные файлы
    из встроенного архива по выбранному диску.
